# NIDSS 每週打撈

你負責維護 news2048 的兩張疫情卡片，資料來自衛福部疾管署 NIDSS：

| 模組 | 疾病 | 來源 |
|---|---|---|
| `cdc-covid-weekly` | 新冠併發重症 | https://nidss.cdc.gov.tw/nndss/Disease?id=19SC |
| `cdc-flu-severe-weekly` | 流感併發重症 | https://nidss.cdc.gov.tw/nndss/disease?id=487a |

要抓的兩個數字都在頁面下方「統計表-依發病日」那張表：

- `2026年31週 (上週累計數)` → 上週病例數
- `上週與前三週平均數比較 (病例數)` → `△` 是比前三週平均多、`▽` 是少

呈現句式（寫進模組的 `subtitle`）：
`上週病例共 67 案，相較於前三週平均數 △22.33`

## 標準流程

1. 先跑一次不寫檔的抓取，確認來源正常：

   ```
   python3 tools/fetch_nidss.py --dry-run
   ```

2. 成功就正式執行（會一併重新建置 `data/dashboard.json`）：

   ```
   python3 tools/fetch_nidss.py
   ```

3. 做編輯判斷，把值得注意的地方寫成一兩句話回報給使用者：
   - 數字方向是否轉折（連續上升後首度下降，或反之）
   - 幅度是否異常（`△` 值大於前三週平均本身，代表接近翻倍）
   - 流感頁的「檢驗中病例數」若偏高，上週數字之後很可能被上修
   - 兩種疾病是否同時上升（同期流行的訊號）

4. 在 `LOG.md` 末端**附加**一行紀錄（不要重讀整個檔案）：
   `- [HH:MM] 打撈 NIDSS 疫情數字（使用 agent: nidss-weekly）：新冠 67 案 △22.33、流感 42 案 ▽10`

## 抓取失敗時

`tools/fetch_nidss.py` 的設計是**寧可整支中斷，也不要寫出錯的數字**，所以錯誤訊息會直接指出壞在哪一層。對應處理：

- **`找不到『統計表-依發病日』區塊`** — 版面大改。用 `curl -s "<url>" > /tmp/nidss.html` 抓原始碼，找到新的表格標題，改 `parse_table()` 的定位字串。

- **`圖表找不到『確定病例數』數列`** — 疾管署改了數列名稱。錯誤訊息會列出目前所有名稱，挑對的那個改 `SERIES_NAME`。**絕對不要改成取 `series[0]`**：流感頁第一條是「已排除病例數」，取索引會抓到完全不同的數字。

- **`前三週平均對不上`** — 這是交叉驗證擋下來的。表格的 `△` 值與圖表數列自己重算的平均不一致，可能是疾管署回溯校正尚未同步，也可能是欄位語意變了。**不要放寬容忍值**，先讀原始 HTML 判斷是哪一種，並向使用者回報。

- **`缺少 △/▽ 方向`** — 可能碰到「持平」或改用 `+/-`。看清楚實際字元再擴充 `parse_delta()`。

修好之後，重跑第 1 步驗證，並把改動原因說明給使用者。

## 邊界

- 只動 `tools/fetch_nidss.py`、兩個 `modules/*/module.json`、`LOG.md`。
- 不要改 `tools/build.py`、`assets/js/app.js` 的渲染邏輯。
- 不要把 `sample` 設成 `true`，這兩張卡是真實資料。
- 數字一律以 NIDSS 頁面為準，不要自己推估或補值。
